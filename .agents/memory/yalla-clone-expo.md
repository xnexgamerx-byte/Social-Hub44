## Key decisions

- **Now full-stack for admin-managed content:** store items + VIP/SVIP tiers + VIP features live in Postgres (api-server `/api`), exposed via OpenAPI-generated hooks; mobile reads them with React Query. Other app data (likes, joined rooms, coins/VIP balance) still AsyncStorage. Admin panel is an IN-APP Expo screen (`app/admin/index.tsx`), not a separate web artifact.
- **Generated client has no `useListX` hooks** — only `getListXQueryOptions()`. Use `useQuery(getListStoreItemsQueryOptions())`. Mutations do have `useCreate/Update/DeleteX` hooks. After admin mutation, invalidate `getListXQueryKey()`.
- **Mobile→API base URL:** `setBaseUrl(\`https://${process.env.EXPO_PUBLIC_DOMAIN}\`)` in root `app/_layout.tsx` (EXPO_PUBLIC_DOMAIN = REPLIT_DEV_DOMAIN). Expo reaches the API cross-origin via absolute URL.
- **Auth = Replit-managed Clerk (whitelabel), server-verified.** Server: `clerkMiddleware` (proxy wired before body parsers), `lib/authz.ts` → `requireAuth` (sets `req.userId` from `getAuth`), `requireAdmin`, `verifySessionToken` for the socket handshake. **Admin model is DB-backed + env bootstrap (not env-only anymore):** `isAdminUserId` resolves the Clerk email then grants admin if it's in `ADMIN_EMAILS` (bootstrap owner) OR in the `admins` Postgres table (email-keyed, lowercase, unique; added via in-app screen). Secure-by-default kept (unresolvable email ⇒ not admin). In-app management = `/admins` CRUD routes (all `requireAdmin`): GET lists env owners read-only (`removable:false`, id 0) + DB admins removable; POST grants by email (rejects env dupes, resolves Clerk id best-effort); DELETE blocks self-removal to avoid lockout. Email-keyed (not userId) so a grant works even before the target signs up. Orval did NOT emit `CreateAdminResponse` — parse the create reply with `ListAdminsResponseItem`. `/api/auth/me` returns `{userId,isAdmin}`. Wallet routes: `router.use(requireAuth)` + `router.param("userId")` enforcing `req.userId===param` (403 cross-user). All catalog WRITES (store-items, coin-packages, daily-tasks, vip-tiers, vip-features) need `requireAdmin` (2nd arg, BEFORE the handler); GET stays public. **Rule:** every money/admin write route needs its auth guard as middleware before the handler — a route that body-validates first will return 400 instead of 401/403, masking that it's unprotected. Audit by hitting each write with no token and expecting 401.
- **Mobile auth:** `@clerk/expo` ClerkProvider in `app/_layout.tsx` (tokenCache via expo-secure-store, proxyUrl), AuthGate redirects signed-out → `(auth)/sign-in`, signed-in → `(tabs)`. `setAuthTokenGetter` + `setSocketTokenGetter` feed the Clerk session token to the REST client and the socket handshake (`socket.handshake.auth.token`). Custom-UI Arabic sign-in/sign-up screens (NOT Clerk prebuilt — breaks Expo Go): email/password (Core v3 `signIn.password→finalize`, `signUp.password→sendEmailCode→verifyEmailCode→finalize`, `nativeID="clerk-captcha"` View) + Google via `useSSO`. Dev env wires `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY`/`EXPO_PUBLIC_CLERK_PROXY_URL` in package.json dev script + build.js. AppContext: `user.id`=Clerk userId, `isAdmin` from `/auth/me`; first sign-in calls `ensureWallet(userId)` (no body) which grants a FIXED server-side welcome balance (`WELCOME_COINS` in `lib/wallet.ts`). **Rule:** no client-facing endpoint may set absolute balances or supply opening amounts — `/wallet/:userId/ensure` once accepted `initialCoins`/`initialVPoints` from the body, letting an authed user mint funds by seeding their own wallet first (onConflictDoNothing = first-write-wins). Opening balance must be a server constant; only validated delta ops (recharge/purchase/claim) move money.
- **Profile editing (name/photo/bio) is Clerk-backed, no backend.** `app/profile-edit.tsx` edits via `@clerk/expo` `useUser()`: display name → `user.update({firstName, lastName:""})` (AppContext derives `name` from `fullName`); bio → `user.update({unsafeMetadata:{...prev, bio}})` since Clerk has NO native bio field; photo → `expo-image-picker` (base64, `mediaTypes:["images"]`) turned into a `data:` URI passed to `user.setProfileImage({file})` (string data URI is accepted by Clerk expo on native). AppContext exposes `bio` from `clerkUser.unsafeMetadata.bio`; `useUser` updates reactively so changes reflect app-wide with no manual refresh. `expo-image-picker` needs its plugin (+`photosPermission`) in app.json. **Gotcha:** form `useState` initializers run before Clerk finishes loading the user, so hydrate name/bio in a one-shot `useEffect` (ref-guarded) once `user` arrives — otherwise fields stay empty and a save can wipe existing bio.
- **Store/VIP screens are locally dark-themed** (store purple/black, VIP brown/gold) — they do NOT use `useColors()`. Don't assume the dark palette below.
- **App is LIGHT-themed.** `colors.ts` light palette: primary `#7C5CFC`, accent `#FF6B9D`, background `#F5F3FF`. `app.json` `userInterfaceStyle: "light"`. (Earlier notes/replit.md saying "dark mode forced / #7C3AED" are STALE.)
- **Real-time layer = Socket.io on the existing api-server**, NOT Firebase/Supabase. Server attaches Socket.io to an `http.Server` (index.ts) at path **`/api/socket.io`** so the shared mTLS proxy (routes `/api`) forwards WS upgrades. Mobile client connects to `https://${EXPO_PUBLIC_DOMAIN}` with that path, `transports:["websocket"]`. Verified WS upgrade works through the proxy.
- **Chat:** messages persisted to Postgres `messages` table (roomId/userId/userName/userAvatar/text). On `room:join` server emits last 50 as `room:history`; new ones broadcast as `message:new`; presence via `room:presence`. Client hook `hooks/useRoomChat.ts` stores chronological, room screen reverses for the inverted list.
- **Ludo is the app's ONLY game (trivia removed).** `lib/gameSession.ts`, `lib/trivia.ts`, the `game:*` socket handlers, `app/game/[id].tsx`, `components/GameCard.tsx`, `hooks/useGameSession.ts` and `data/mockData.ts` are all deleted — don't resurrect them. Two table sizes: `mode: 2 | 4`, fixed by whoever opens the table (`ludo:join {mode}`) and echoed back as `mode`/`maxPlayers` in the snapshot. **A duel MUST seat red+yellow** (`DUEL_COLORS`), not red+green — the ring start offsets are 13 apart, so adjacent colours would hand one player a 13-cell head start. A join at a full table gets `ludo:error` instead of a silent spectator view.
- **Board geometry lives in `lib/ludoBoard.ts`**, rendered by `components/LudoBoard.tsx`. The server's position model is numeric only (-1 yard, 0..50 ring relative to the colour's start, 51..56 home column, 57 finished); the client maps it to a 15×15 grid via the 52-cell `RING` array, `HOME_COLUMN`, and `yardSlots`. Ring index 0/13/26/39 are the red/green/yellow/blue entries and must stay in sync with `START_OFFSET` + `SAFE_CELLS` on the server. Tokens animate between cells and co-located tokens fan out via a stack offset. **The movable-token pulse loop is stopped in the effect cleanup**, not just on completion.
- **The ludo table reuses the room stack for social features.** `useRoomChat`/`useRoomVoice`/`useRoomGifts` are called with `roomId = \`ludo:${gameId}\`` — chat persists to the `messages` table, mic seats and gifts work unchanged, and no parallel systems were built. The table id doubles as the invite code shown in the header; the games screen joins by typing it.
- **(historical) Multiplayer trivia was SERVER-AUTHORITATIVE** (`lib/gameSession.ts` + `lib/trivia.ts` on api-server). Server runs the loop (question→reveal→advance), broadcasts synced `game:question {endsAt}`, `game:reveal`, `game:end`; clients only render + submit `game:answer`. Speed-based scoring computed server-side at reveal. Client hook `hooks/useGameSession.ts`; countdown derived from shared `endsAt` timestamp. Questions live on the SERVER now (client `TRIVIA_QUESTIONS` no longer drives gameplay).
- **Voice rooms are "Agora-ready", not live-audio yet.** Real audio (`react-native-agora`) is a NATIVE module that Expo Go cannot load and Replit's Expo preview is Expo-Go-based — so installing it would break the preview, and Replit only publishes iOS (Expo Launch), not Google Play. Decision (user agreed): build everything EXCEPT audio transport now. The live mic STAGE (who's on mic / who's muted, max 12 seats) syncs over our Socket.io via `lib/roomVoice.ts` (in-memory seats) + events `mic:join`/`mic:leave`/`mic:mute` → broadcast `mic:state`; snapshot sent on `room:join`; `mic:full` when stage maxed. Client hook `hooks/useRoomVoice.ts`. Server token endpoint `GET /api/agora/token?channel&uid` (`routes/agora.ts`, `agora-token` pkg, PUBLISHER role, 1h TTL) returns 503 when `AGORA_APP_ID`/`AGORA_APP_CERTIFICATE` secrets absent. Client bridge `lib/agoraVoice.ts` (`fetchAgoraToken`, `uidFromUserId`) has the native RtcEngine drop-in documented in comments. **How to apply:** to go fully live, prebuild off Expo Go, install react-native-agora, wire it in `agoraVoice.ts` using the existing token + seat state. Do NOT install react-native-agora into the running Expo Go app.
- **Inverted FlatList for chat** in `app/room/[id].tsx` — never use scrollToEnd().
- **KeyboardAvoidingView** from `react-native-keyboard-controller` (not RN built-in).
- **NativeTabs** on iOS 26+ with liquid glass; classic BlurView Tabs fallback.

## Growth systems — and the line we do NOT cross

- **No fake-human accounts, ever.** The user asked for bot personas ("بنات وشباب بجنسيات مختلفة") that DM real users. Declined and must stay declined: the app sells coins for real money, so personas that pose as people are consumer fraud (regulators have fined dating apps for exactly this) and get the app pulled from both stores. The legitimate substitutes are all built instead — see below. What apps like Sugo actually run is a **paid-host** programme with real people, not bots.
- **Referrals:** each wallet's existing 8-digit `publicId` doubles as the invite code — no second identifier. `GET /referrals/me`, `POST /referrals/claim {code}`. One claim per account enforced by an explicit pre-check *and* the unique index on `referrals.referredId` (the index is the race backstop; catch checks `err.code` **and** `err.cause.code` for 23505). Self-referral rejected. Both credits + the claim row happen in one transaction. Screen: `app/invite.tsx`.
- **Gift earnings + paid hosts:** recipients now earn `giftEarnings(price, hostBonus)` in vPoints — `GIFT_RECIPIENT_SHARE` 0.3 plus the host's `bonusSharePercent`. This is the earning side of the economy (coins bought → vPoints earned) and how hosts get paid. Credit happens *after* the sender's debit and never to the sender; a failed payout is logged, never rolled back onto the gift. `hosts` + `host_sessions`; socket records a stint on room leave/disconnect, dropping anything under a minute so reconnects don't pad hours. Admin-only `/hosts` CRUD keyed by public account id.
- **Official account:** `official_nabda`, `profiles.isOfficial`, seeded by `ensureOfficialProfile()` in `seed.ts`. Sends one welcome DM when a profile row is *first* created (the upsert route checks existence beforehand). Rendered with a "رسمي" badge; hosts get a "مضيف" badge. **Any automated account must be visibly labelled.**
- **Push:** `push_tokens` + `lib/push.ts` (Expo Push API, prunes `DeviceNotRegistered` tokens). Fires on new DMs. Remote push does **not** work in Expo Go (SDK 53+) — `lib/push.ts` on the client no-ops there; it activates on the first real build with no further wiring.
- **Scheduled sessions:** `room_events` (+ optional `weekday` for a weekly slot), admin-created, shown as a horizontal strip on the rooms tab.
- **Metro gotcha hit again:** newly installed packages resolve as "not found" until Metro restarts with `--clear`.

## User directory + moments are DB-backed (no longer mock)

- **`profiles` table is the app's user directory.** Clerk owns auth but is not queryable as a feed source, so `AppContext` upserts `POST /profiles/me` (name/avatar/bio/gender/age) whenever the Clerk identity changes, guarded by a signature ref so it fires once per change. Every write is keyed to the authenticated id — the body cannot name another user. `GET /profiles` excludes the caller, orders by `lastSeenAt`, joins wallet XP for `level`, and derives `isOnline` from a 5-minute `lastSeenAt` window (the upsert refreshes it). `GET /profiles/:userId` for one user. **Anything needing a display name server-side should read profiles, not Clerk.**
- **Moments = `posts` + `post_likes`.** `GET /posts` batches likes/levels/profiles (no per-post queries) and returns `likeCount` + per-viewer `likedByMe`; author name/avatar come from the *live* profile with the stored snapshot as fallback, so renames propagate. `POST /posts` takes text/images/tag (authorship from session), `DELETE /posts/:id` is author-or-admin and clears likes in the same transaction, `POST /posts/:id/like` toggles idempotently. Images are `data:` URIs (quality 0.6, max 4) since there is no upload service — swap to real storage before scale. Screens: `(tabs)/videos.tsx` is the feed (tab is labelled اللحظات), `app/post-create.tsx` composes.
- **`data/mockData.ts` now holds ONLY the `GAMES` catalogue.** NEARBY_USERS/POSTS/VIDEOS/ROOMS are gone — every social surface is DB-backed. `components/VideoCard.tsx` is currently unreferenced (kept for a future video feature).
- **Rule: never ship a control that only fires haptics.** The home and moments chat buttons did exactly that, and two tab bars filtered nothing. If a control has no destination yet, remove it rather than leaving it inert.

## Rooms + DMs are DB-backed (no longer mock)

- **Rooms:** `rooms` table (ownerId = Clerk userId, category chat|gaming|music|family, tags text[]). Routes in `routes/rooms.ts`: GET /rooms + /rooms/:id public, GET /rooms/mine + POST (max 3 active/user, ownerId always from auth) + PATCH/DELETE (owner-or-admin) behind requireAuth. `/rooms/mine` MUST be declared before `/rooms/:id`. Starter rooms seeded (ownerId "system") via seedIfEmpty. Mobile: `(tabs)/rooms.tsx` uses `getListRoomsQueryOptions`/`getListMyRoomsQueryOptions` ("أنا" tab shows my rooms with edit/delete), `app/room-create.tsx` creates/edits (ref-guarded hydrate), `room/[id].tsx` loads via `getGetRoomQueryOptions(Number(id))`. ROOMS mock removed from mockData.ts; RoomCard now takes the generated `Room` API type.
- **DMs:** `conversations` (canonical pair userAId<userBId unique, per-side unread counters + display snapshots) + `dm_messages`. Shared logic in api-server `lib/dm.ts` (getOrCreateConversation upsert-with-race-retry, sendDm = transaction insert+conversation bump, shapeForUser). REST `routes/dm.ts` (all requireAuth): GET /dm/conversations, POST /dm/open, GET /dm/conversations/:id/messages, POST /dm/conversations/:id/read — participant-checked. Real-time: every socket joins personal channel `user:<authUserId>` on connect; `dm:send` (identity from socket auth, payload names display-only) → emits `dm:new {message, conversation-shaped-per-recipient}` to both users' channels, `dm:error` on failure. Mobile: `(tabs)/messages.tsx` real inbox (dm:new invalidates), `app/dm/[id].tsx` chat (history query + live socket merge, mark-read on open/incoming), entry point = tapping a member's avatar in room chat → useOpenConversation → navigate. Generated hooks quirk: single-GET options helpers (`getGetRoomQueryOptions`) must be spread into `useQuery({...opts, enabled})` — passing `{query:{enabled}}` to `useGetRoom` fails typecheck (queryKey required).
- **Windows local dev:** pnpm-workspace.yaml no longer excludes win32-x64 binaries (esbuild/lightningcss/oxide/rollup) so the repo also installs on Windows; Replit (linux) unaffected. drizzle.config.ts normalizes the schema path to forward slashes (drizzle-kit globs break on backslashes).

## Levels + follows (server-authoritative)

- **XP/level:** `wallets.xp` bigint accumulates inside `adjustWalletTx` via `xpGainFor(type, amount)` — abs(amount) for recharge/gift_sent/purchase/task_reward, 0 for adjust/gift_received. Level derived (never stored): `levelForXp(xp) = min(99, floor(sqrt(xp/100)) + 1)`. Wallet responses include xp+level; AppContext user.level reads walletQ.
- **Follows:** `follows` table (followerId/followedId, unique pair, idempotent onConflictDoNothing). Routes `routes/follows.ts` (all requireAuth): POST /follow {targetUserId} (400 self-follow), DELETE /follow/:targetUserId, GET /follow/stats/:userId → {userId, followers, following, isFollowedByMe (relative to caller)}. AppContext user.followers/following from own stats query; DM chat header has follow/unfollow button + follower count.

## Coins economy (SUGO-style)

- **Two currencies:** `coins` (كوينزات, gold) — bought via coin packages, spent on live gifts; `vPoints`/`V` (diamonds, purple) — earned, spent on frames/entrances/etc. Wallet is backend-authoritative (`wallets` table) with a `wallet_transactions` ledger; `lib/wallet.ts` does atomic adjust+ledger. AppContext reads coins/vPoints from the wallet via React Query.
- **VIP is server-validated now (NOT AsyncStorage).** `wallets.vipLevel`/`vipType` ("" | vip | svip) + `POST /wallet/:userId/vip {level,type}` in routes/wallet.ts: tier must exist+active and `wallet.vPoints >= tier.pointsRequired` (threshold-based like SUGO — activation is a status change, does NOT spend points). AppContext `setVip` is async (useActivateVip → invalidate wallet); user.vipLevel/vipType derive from walletQ. vip.tsx disables the button and shows "نقاطك غير كافية" when ineligible. The old local `userState` AsyncStorage vip blob is dead — never reintroduce a client-set VIP.
- **store_items.itemType** drives behavior: `gift` (priced in coins, sent live into rooms), `entrance` (equipped, plays on room join), `frame`/`background`/`symbol`/`recovery` (cosmetic). Gifts/entrances are seeded store items, NOT separate tables.
- **Live gifts + entrances over Socket.io:** client emits `gift:send {roomId,userId,itemId,...}`; server deducts coins, broadcasts `gift:new` + `wallet:update` (or `gift:error`). On `room:join` server broadcasts `room:entrance` using the joiner's equipped entrance. Client hook `hooks/useRoomGifts.ts` + overlays `GiftOverlay`/`EntranceOverlay` (call `onDone(event.key)`), picker `GiftPicker`. `useRoomChat(id, me)` must pass `{userId,userName,userAvatar}` so the server knows who joined.
- **Gift/entrance effects are full-screen + queued.** `useRoomGifts` holds FIFO queues for gifts and entrances and only exposes the head as `gift`/`entrance` (room screen API unchanged); `clearGift/clearEntrance` pop the head so a rapid burst plays one-at-a-time instead of overwriting. `GiftOverlay` tiers richness by gift coin price via `lib/giftTier.ts` (particles/glow rings/scrim/spin/hold) using RN `Animated`. Centerpiece comes from `components/GiftMedia.tsx`, which picks a renderer from the item `mediaUrl` extension: video→`expo-video`, lottie(.json/.lottie)→Lottie, image/gif/webp→`expo-image`, none→gradient icon. **Why empty `mediaUrl` still looks good:** seeds have `mediaUrl:""`, so the tiered Animated effect (not the media) is what plays today.
- **Animated effects must stop loops in the effect cleanup `return`, not only the completion callback** — leaving a room mid-effect otherwise leaks running loops. Also: a per-event Animated.Value array must be a FIXED-size pool (max tier count) so a bigger gift after a smaller one never indexes past the array.
- **Admin** (`app/admin/index.tsx`) has 6 tabs: store (with itemType selector + mediaUrl), packages (coin packages CRUD), tasks (daily tasks CRUD), VIP tiers, features, المشرفون (admins: add by email / remove, env owner read-only, + grant/revoke history "سجل التغييرات").
- **Admin audit trail:** append-only `admin_audit` table (action grant|revoke, targetEmail, actorEmail, createdAt; NO FK to `admins` so history survives deletes). POST/DELETE /admins write the admin mutation + audit row in ONE `db.transaction` (grant/revoke must never apply without its history entry). GET /admins/audit (requireAdmin, latest 100 desc). actorEmail is best-effort ("" if Clerk email lookup fails) — don't fail the action over a transient lookup since the requester is already admin-gated.
- **CoinPackage.price is a string** ("$9.99") not a number. DailyTask.reward is coins.

## Testing

- **api-server has Vitest** (`pnpm --filter @workspace/api-server run test`, registered as the `test` validation step). Pattern for route/authz tests: `vi.mock("@clerk/express")` with a `vi.hoisted` identity state (controls `getAuth().userId`, `clerkClient.users.getUser/getUserList`) so tests drive real `requireAdmin`/route/DB logic without Clerk network; mount the router on a bare `express()` app and drive it with `supertest`. Tests hit the REAL dev Postgres — isolate rows with a unique `TAG = vitest_${Date.now()}` email suffix and `LIKE %TAG%` cleanup in afterEach/afterAll. **Do NOT call `pool.end()` per test file** — each Vitest file runs in its own forked worker torn down on completion, so ending the shared `@workspace/db` pool would break future test files. Config `vitest.config.ts` runs serially (`fileParallelism:false`, `sequence.concurrent:false`) since files share the DB. Test files live in `src/**/*.test.ts` (typechecked by `src` tsconfig; not bundled since esbuild entry is only `src/index.ts`).
- **Socket.io tests** (`src/lib/socket.test.ts`): drive a real socket server with `socket.io-client`, mocking ONLY `@clerk/backend` `verifyToken` (token `valid:<userId>` → `{sub:userId}`) so the real handshake middleware + handlers run. Durable lessons that bit us: (1) socket identity is server-side only — sensitive events (`message:send`, `gift:send`, `mic:*`) trust `socket.data.userId` and ignore any payload `userId`, so spoof tests assert the *authenticated* id wins (gift attribution + wallet debit, not the payload's). (2) Async-event tests are race-prone: always register the listener BEFORE `emit`, guard waits with timeouts, and assert non-delivery with a timed "expect no event". (3) `room:join` emits an initial empty `mic:state` snapshot first — wait on a predicate, not a bare first-event. (4) Game/room broadcasts are channel-scoped (`game:<id>`/`room:<id>`); cross-isolation tests confirm one channel's events never reach another. (5) Trivia `game:start` schedules a 15s question timer — purge the session (`leaveGame`) at test end so the timer is cleared.

## Gotchas (durable)

- [Metro stale resolution after codegen](metro-stale-codegen-cache.md) — Metro caches "module not found" for freshly codegen'd files and persists it across workflow restarts.
- **Vector-icon fonts must be loaded explicitly in `useFonts`, or icons render blank on Android.** Root `app/_layout.tsx` gates render on `useFonts(...)`. Loading only the custom (Inter) fonts and returning null until ready makes `@expo/vector-icons` (Ionicons/Feather) glyphs fail to register in time — on Android Expo Go they show as empty/invisible (icons look like solid colored circles with nothing inside; web is unaffected). Fix: spread each used family's `.font` into the same `useFonts` call (`...Ionicons.font, ...Feather.font`). **How to apply:** whenever a root layout blocks on `useFonts`, every icon family used anywhere in the app must be in that call.
- **External image hosts (pravatar.cc, picsum.photos) are blocked/slow on the user's Android; fine on web (Replit-proxied).** Symptom: blank avatars/images on device only. Fix: every remote image needs a graceful `onError` fallback — `components/UserAvatar.tsx` renders a hash-colored initial circle; post images fall back to an icon placeholder. **How to apply:** never render a bare `<Image uri=...>` for remote content; route avatars through UserAvatar and other remote images through a fallback wrapper.
- **AuthGate is the ONLY place that redirects on auth state.** The sign-in/sign-up screens used to also `router.replace("/(tabs)")` from Clerk's `finalize({navigate})` / `setActive({navigate})` callbacks. Those fire before the root navigator has mounted `(tabs)`, so every successful login logged "The action 'REPLACE' … was not handled by any navigator". Their `finishNavigate` is now a no-op and `setActive` is called without `navigate`; AuthGate (guarded on `useRootNavigationState()?.key`) does the redirect when `isSignedIn` flips. **How to apply:** never navigate on auth completion from a screen — let the gate own it.
- **Clerk instance settings must match what the auth screens collect.** A fresh Clerk app defaulted to: allowlist restriction ON ("<email> is not allowed to access this application"), `phone_number` required (sign-up and Google SSO both fail — the form never collects a phone, and Google supplies none), and `password.used_for_first_factor: false` (email+password sign-in rejected). Diagnose without guessing by fetching the public env: `curl "https://<fapi-host>/v1/environment?__clerk_api_version=2021-02-05&_clerk_js_version=5.35.0"` and reading `user_settings.restrictions` / `.attributes` / `.social`; the FAPI host is the base64-decoded publishable key. Errors are surfaced via `lib/clerkError.ts` — don't replace Clerk's message with a generic string.
- **Root-level auth redirect must wait for the navigator to mount.** `AuthGate` in `app/_layout.tsx` calls `router.replace("/(tabs)")`/`"/(auth)/sign-in"` from a `useEffect`; if it fires before the root navigator mounts, expo-router throws "The action 'REPLACE' ... was not handled by any navigator. Do you have a route named '(tabs)'?". Gate the effect on `useRootNavigationState()?.key` being truthy (and include it in the dep array). **How to apply:** any programmatic navigation from a root layout effect needs this guard.
- **Seed must be idempotent per item-type, not all-or-nothing.** `seed.ts` originally guarded store_items insert on `count===0`; once frames were seeded, later-added gift/entrance types never inserted. Fix: backfill only itemTypes not already present (`selectDistinct(itemType)` → insert missing). Same trap applies any time you add new seed rows to an already-populated table.

**Why:** Social entertainment apps need dark, rich palettes; AsyncStorage avoids backend complexity for MVP.
**How to apply:** Adding new screens should respect dark palette from colors.ts via useColors() hook.
